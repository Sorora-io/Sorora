## Tracking plan

Direct mixpanel-browser 2.84.0; no Segment, RudderStack, existing analytics or consent interface found. All events require explicit opt-in. No events are buffered or replayed from before consent.

| Event | Trigger |
| --- | --- |
| page_viewed | Initial consented page and subsequent pathname changes; duplicate effect calls suppressed |
| sign_up_completed | Supabase confirms a newly created account with nonempty identities; email verification may still be pending |
| login_completed | Successful explicit password login; not session restore/token refresh |
| ranking_submitted | Ranking and associated preference writes both succeed; repeat saves count as submissions |
| matching_completed | Matching RPC succeeds |
| pairings_updated | Manual pairing changes persist successfully |
| reveal_requested | Reveal endpoint returns a result; does not imply every email was delivered |
| reveal_scheduled | Reveal schedule saves successfully |
| reveal_cancelled | Reveal cancellation succeeds |

Every event has platform=web. Only page_viewed adds a sanitized route template (page). Unknown routes become not_found. No names, emails, Sorora user IDs, chapter/cycle IDs, rankings, capacity preferences, pairing members, free text, query strings, fragments or referrers are sent. An allowlist filters SDK defaults at the final send boundary. Autocapture, automatic pageviews, recording, heatmaps, marketing attribution and IP geolocation are disabled. Mixpanel still receives browser network connections after consent; ip=0 disables IP-based enrichment, not ordinary network transport.

Identity intentionally differs from the generic Mixpanel identify/profile recipe: no identify or people calls. A random browser identifier supports within-session journeys, resetting on app reload, logout/account switch, and re-opt-in. It cannot measure unique people or cross-device retention. This follows the user's restriction on sensitive data and avoids exporting account identifiers.

## Consent

Analytics preferences appear on all app pages, with equally styled Allow/Decline actions. The essential localStorage choice is sorora.analytics-consent.v1. Unknown, invalid, unavailable storage, or declined consent prevents initialization/tracking. Withdrawal clears SDK persistence and prevents subsequent sends, including across tabs; events already sent are not deleted. Failed preference writes fail closed for that open app. The interface remains available to change the choice.
